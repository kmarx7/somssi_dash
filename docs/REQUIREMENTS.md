원본 해시/셀별 내용/병합/페이지 설정은 original-inventory.json에 기록했다. 원본 양식의 예시 이름과 예시 지출은 실제 데이터로 수집하지 않는다. 공식 Office 파일은 public 및 Git에 포함하지 않는다.

## 기존 HTML과 명세의 차이

- 참고 HTML은 localStorage에 업무/회의/지출을 저장한다. 실사용 영속성·권한이 없으므로 그대로 이식하지 않는다.
- 지출 삭제 버튼은 거래 보존 규칙과 충돌한다. 새로운 시스템은 정정·역분개·보완 이력으로 처리한다.
- 참고 화면의 CSV는 공식 XLSX 출력이 아니다. M1에서는 생성/저장/승인 버튼을 비활성화한다.
- 기존 배분표는 외부 앱이다. 실제 지출·승인액·정산액으로 간주하지 않는다.

## 확정 요구사항

원본 Office 바이너리 복제 기반 주입, 원본 구조/서식/사진·서명 위치/수식·유효성·인쇄 설정 보존. 원본 배분표 계산·상호작용·화면 유지. 공통 UUID 및 프로젝트 범위 참조. 원화 bigint. 승인 신청과 실제 집행 분리. 집행 거래 삭제 금지. 서버 인가/RLS/private Storage/단기 URL. 규정 버전 및 생성 스냅샷/원본·결과 해시. 문서 렌더 비교 실패 시 제출 차단. 데모와 실제 데이터 분리.

## 확인되지 않은 항목과 후속 결정

- 2R 자료 폴더에서 기존 앱 HTML 4종을 확보했다. 예산·일정의 인라인 CSS/JS는 배포본과 동일하지만 회의록·이메일은 다르다. 해당 두 앱의 최신 기준본·변경 내용과 전체 회귀 검증은 M3에서 확정한다.
- 멘토기관 최신 규정 버전/유효기간/승인권자/자기승인 제한, 실제 일정·팀원·지출은 미확정.
- Word 렌더와 폰트 기준, 필드별 허용 길이·사진 크기, Excel 용지/프린터 기준은 M5에서 확정.
- 원본에 생년월일·연락처 필드가 존재하나 수집 법적 근거/접근 역할/보존기간을 먼저 결정한다.
- team_participation은 프로젝트 단위 다인 문서이므로 팀원 1명과 문서 1개를 동일시하지 않는다.

## M1 구현 전 계획 및 완료 범위

기존 UI는 사이드바/상단/카드 구조가 있으나 10개 메뉴와 가짜 저장 동작이 섞여 있다. 새 웹앱은 명세의 전체 IA, 네이비 사이드바와 밝은 콘텐츠, 일관된 상태 배지, 모바일 접기 메뉴, 키보드 초점과 건너뛰기 링크를 제공한다.

apps/web에 Next.js App Router + React + TypeScript + Tailwind, 공통 Shell/Panel/Badge/페이지 헤더, 경로 메타데이터, 별도 data/demo를 구성한다. 개요·대시보드와 데모 업무 필터는 작동하며 나머지는 설명/예정 단계/원본 링크가 있는 화면이다. 로그인 화면도 인증 미구현을 표시한다. 알려지지 않은 경로·상세 ID는 404다.

이번 단계는 인증·DB·쓰기 API·문서 생성·업로드·정산 계산·실시간 협업·배포를 구현하지 않는다. 샘플 업무 상태 변경이나 승인 처리도 하지 않는다. 회의록·이메일 배포본 차이 및 Office 출력 렌더 미검증으로 M0 전체 완료를 주장하지 않는다.

## 추가 발견한 기존 앱 소스 분석
