# 원본 양식 로컬 자동 작성

## 범위

실제 제공받은 회의록·활동비 증빙·물품 구매 사유서 DOCX와 창업활동자금 세부내역 XLSX를 복제해 입력한다. 원본 Office를 Git/public에 두지 않는다. 회의 날짜·목적/내용·실제 참석자/시간 등은 documentDrafts에, 금액·거래처·집행일·비목은 기존 expenses에 한 번 저장하고 초안의 expenseIds로 참조한다. 거래명세·견적은 estimates로 구분하여 실제 지출 합계에 자동 포함하지 않는다.

회의비는 회의록으로 작성하며 별도 활동비 지출이 없는 회차는 활동비 증빙을 만들지 않는다. 주차 등 분류가 미확정인 지출은 적격성/비목 확인 대상으로 남긴다. 신청·정산 승인 기능이 아니다. 실제 운영 실적을 문서 작성만으로 생성하지 않는다.

지원: 원본 복제·지정 칸 텍스트 입력·선택 지출 합계·미확인 표시·DOCX 렌더/페이지/안내문 가림 확인·Excel 계산/미리보기·원본 구조 비교·스냅샷/해시·감사 이력·개별/ZIP 다운로드. 현장·물품사진의 Word 칸 삽입과 본인 서명은 수동이다. 캡처/영수증을 현장사진이나 서명으로 대체하지 않는다. 팀원 참여 확인서와 2R 사업계획/활동보고 양식 생성은 지원하지 않는다.

## 사용법

1. `/documents`에서 입력 초안을 등록/수정한다. 원본 종류, 근거 일정, 실제 사실과 출처를 입력하고 해당 실제 지출을 선택한다. 사용하지 않는 초안은 보관 상태로 변경한다.
2. 작성할 초안을 선택해 `작성(검토용)`을 실행한다. 활동비3행·세부내역21행을 넘기거나 자금을 혼합하면 실패로 알린다. 모든 생성 결과는 검토 필요 상태다.
3. 결과와 미입력/검토사항을 확인하고 DOCX/XLSX 또는 전체ZIP을 받는다. 누락된 실제 내용·참석자·시간·사진·서명·기관 판단을 보완하고 제출한다. 입력을 수정해 다시 작성하면 새 버전 스냅샷과 이력을 만든다.

기관 안내문의 회의비·가족 관계·활동비 등 원문 규정은 원본에 그대로 남긴다. 본문 슬롯은 원본의 고정 높이/들여쓰기를 유지하므로 길면 입력을 요약해야 한다. 원본 고정 칸이나 주요 문구가 가려지면 작성 실패로 처리한다. 상세 회의록은 원본 양식을 첫 페이지로 유지하고 같은 파일 뒤에 별첨을 추가하며 전체2~4쪽을 검사한다. 활동비·구매 사유서는 원본1쪽을 유지한다. 사진 선택은 참고용 연결이며 Word에 자동 삽입하지 않는다.

## 비공개 저장/준비

기본 경로: `.somssi-local/documents`. `templates`에 원본 네 가지와 선택적인 영수증PDF, `manifest.json`(파일별 SHA-256)을 둔다. 정확한 파일명은 source 코드의 templateFiles 및 services/docgen/generate.py의 FILES를 따른다. 원본을 바꾸면 새 해시/버전으로 등록하고 기존 원본을 별도로 보존한다. 런타임은 같은 컴퓨터의 `runtime.json`에 절대경로로 설정하며 HTTP 입력으로 실행 파일 경로를 받지 않는다.

필요 키: python(lxml/pypdf를 포함한 준비된 Python), node(@oai/artifact-tool 지원 Node), artifactModules, renderer(패키지 render_docx.py), runtimeBin(번들 LibreOffice/Poppler), 선택 fontConfig. 패키지/원본 미준비 또는 해시가 다르면 실행을 차단한다. 이 컴퓨터에는 제공된 Codex 번들 의존성을 연결했다. 사용자 데스크톱 LibreOffice로 자동 대체하지 않는다. 한글이 없는 번들 폰트는 별도 비공개 fontconfig의 로컬 한글폰트로 렌더하며 DOCX의 글꼴 속성을 바꾸지 않는다. 다른 컴퓨터는 이 경로를 다시 준비해야 한다.

`jobs/<UUID>`에 데이터 스냅샷, 원본/결과 해시 목록, 작성 파일, 렌더 QA, 검토사항,ZIP을 저장한다. 생성 실패는 비공개 failure.log와 실패 생성 이력에 남긴다. 생성 기록은 불변이며 다운로드 시 생성 이력/허용 파일명/목록 해시/파일 해시를 확인한다. 초기 레이아웃 보완 전 시험 출력은 다운로드를 차단하고 재작성을 안내한다. 모든 API는 기존 loopback Host/동일 Origin 보호를 재사용한다.

기존 증빙 포함 운영 백업은 DB·증빙 범위이며 템플릿/런타임/작성 작업 폴더 전체를 포함하지 않는다. 작성 ZIP과 비공개 documents 폴더를 별도로 보관해야 결과 파일까지 복구할 수 있다. DB 복구 후 결과가 없으면 파일 누락으로 표시하고 원본/런타임 재준비 후 다시 작성한다. 이를 전체 작성 파일의 자동 백업 완료로 표시하지 않는다.

## 원본 보존 방식

DOCX는 word/document.xml의 지정 텍스트만 치환한다. 다른 모든 ZIP 파트와 styles/theme·표/병합/행/페이지 속성은 비교해 불변을 검사한다. 규정 안내문은 별도 보존한다. 서명은 생성하지 않는다.

Excel은 artifact-tool에서 원본을 읽고 값/수식을 계산·미리보기한 뒤, 해당 후보의 A6:J26 값만 원본 worksheet XML에 옮긴다. 원본 I27 SUM 수식은 유지하고 계산 캐시를 갱신한다. 원본 styles·시트·병합·유효성검사·인쇄 관련 파트는 그대로 유지한다. 원본 날짜 표기 관례를 따르며 날짜열은 계산에 사용하지 않는다. 좁은 거래처 칸은 긴 이름을 말줄임 표시하고 전체 이름을 비고에 함께 보존한다. 예시 거래/예시 인물은 출력에서 지운다. 자료에 없는 예시 운임을 실제 지출로 수입하지 않는다.

## 데이터/검증

새 도메인 documentDrafts, documentGenerations는 기존 SQLite records/links/audit를 재사용한다. DB 초기화·기존 원장 수정·지출 삭제가 없다. 실패 시 입력은 보존한다. 기존 지출 정정은 원거래를 남기는 기존 정정 절차로 처리하고 출력에 반영할 거래를 다시 선택한다. 생성 시점 스냅샷은 목록 읽기 트랜잭션으로 고정한다.

소스: lib/documents/service.ts, app/api/documents, components/documents/document-center.tsx, services/docgen. 설치된 Next 문서의 route.md와 공식 Route Handlers 문서(https://nextjs.org/docs/app/getting-started/route-handlers)를 확인했다. 실제 테스트 범위와 남은 제약은 TEST_PLAN.md에 기록한다.

## 파일명·이전 회의 확인 (2026-10-30)

다운로드 이름은 `SOMSSI_회의록_제2차_2026-10-27.docx`처럼 문서 종류·회의 차수·날짜로 표시한다. HTTP Content-Disposition의 UTF-8 filename*과 화면의 download 이름을 동일하게 설정한다. 내부 UUID 파일명은 경로 검증/해시용으로 유지하며 외부 표시 이름과 분리한다. ZIP 내부도 같은 한글 이름을 사용한다. 기존 생성본의 개별 다운로드는 표시 이름으로 변환하지만 과거 ZIP 내용은 보존하므로 한글 ZIP 항목을 받으려면 재작성한다.

회의 초안에 선택적인 meetingNumber, previousDraftId, previousReview를 추가했다. 이전 회의는 같은 도메인의 더 이른 날짜를 참조하며 자기/미래/비회의 참조를 차단한다. 차수는 선택 순서로 재번호를 매기지 않는다. 기존 초안/백업은 새 필드가 없어도 원래 payload와 감사 이력을 유지해 복구할 수 있다.

상세 본문은 원본 표를 늘이거나 글꼴을 줄이지 않고 별첨 문단으로 출력한다. 이전 초안의 검토 과제, 이후 기록에서 확인된 내용·미확인 사항, 현재 업무 기록·구체 검토안, 후속 실행안, 증빙·출처를 구분한다. 업무 메시지를 당시 회의의 확정 의결로 바꾸지 않으며 사후 확인한 정보는 소급 의결로 쓰지 않는다. 입력은 로컬 감사 이력으로 버전 관리한다.
