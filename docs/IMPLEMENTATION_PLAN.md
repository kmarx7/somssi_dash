# 단계별 개발 순서

각 기능은 feat/<기능명> 브랜치에서 개발·테스트·push한다. 사용자의 요청 없이 main에 병합하지 않는다. 이번 브랜치: feat/m1-web-shell.

| ---------------- | -------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |

## 첫 단계 파일 계획

apps/web/app: 공통 layout, (main) layout, 개요·대시보드·업무, 나머지 메뉴 안내 라우트, login, not-found. components: shell/navigation/ui/feature 안내. lib: 경로·외부 연결 메타데이터. data/demo: 고정 예시만 보관. docs: 요구사항·DB/흐름·필드매핑·디자인·테스트. scripts: 원본 해시 검사/메뉴 경로 smoke 검사.

M2 전에 실제 일정과 업무 목록·멘토기관 규정·승인자를 확정한다. M3의 배포본 차이 확인와 M5의 렌더 기준 준비는 병행 가능하지만 사용자 지시 없이는 이번 단계에서 기능을 확장하지 않는다.
