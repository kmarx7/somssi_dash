## 구현과 보존

기존19개 계획의 내용·출처를 보완하고 신규5개(영문 준비, 경쟁/통계 근거, 가격 단계, 사진·권리, 지역 동선/실제 방문)를 추가해24개로 구성했다. 고정 ID를 유지한다. sourceRegistry/사업계획/상품/문서 화면의 미확보 안내를 갱신하고 가격을 참조 가설로만 표시한다. 실제 상품·결제·참가·팀원 데이터는 생성하지 않는다.

`data/reference/schedule-plan-v1.ts`는 이전 자동 생성값을 보존하는 공개 가능한 계획 정의다. `schedulePlanChanges`는 기존 레코드와 이전 자동값을 비교하여 제목/내용/출처/확인일이 그대로인 필드만 갱신한다. 사용자가 수정한 제목·내용·출처·기간·시간·색상·담당자·관련 업무·증빙·상태를 보존한다. 완료/취소 기록 전체는 갱신하지 않는다. 신규항목만 추가하거나 미반영 필드만 갱신하여 재시도·재실행 시 중복/덮어쓰기를 방지한다.

모든 반영은 기존 POST /api/records → Zod → SQLite 버전검증/감사를 재사용한다. 오류 시 이미 반영한 개수와 재시도 안내를 표시하며 24개 전체의 단일 트랜잭션은 아니다. 기존 DB schema·예산 원본·Office 원본·API는 변경하지 않았다. 사용자는 일정 화면의 `사업계획 기준 n개 반영`으로 같은 보완을 적용할 수 있다.

사전 백업: Git 제외 `.somssi-local/backups/before-final-plan-20261030.somssi-backup.gz`. 원본 DOCX 사본은 운영DB/증빙 백업에 자동 포함되지 않으므로 원래 다운로드 파일과 비공개 reference-sources 사본을 별도로 보관한다.

확인 필요: 공식 사업계획·활동보고 HWP, 실제 파일럿/멘토링 운영일, 팀원의 실제 관계/참여기간, 실측 실적/증빙, 상표출원 실제 상태, 제출 서식/페이지 수. 이 파일만으로 실적이나 공식 양식 검증 완료를 판정하지 않는다.

실제 적용 결과: 사전 백업 후 기존19개 보완+신규5개를 서버 API로 반영했다. 총24개·미반영0·누적감사43·전부계획, 매출/지출0을 확인했다. 브라우저 재탐색 후 유지되며 원본 사본 웹경로는404이다. 필수4종·단위38개·실제API 통합·브라우저 결과는 TEST_PLAN.md에 기록했다.
