# 로컬 저장 전환 — 2026-10-30

사용자의 ‘로컬로 저장하는 것으로 바꿔줘’ 요청에 따라 기존 클라우드 저장 선택을 대체했다. 웹 UI/업무/집계/예산 원본은 유지하며 Supabase SDK·서버 클라이언트·이메일 로그인 폼을 제거했다. 원격 서비스와 기존 브라우저 localStorage에는 접근하거나 변경하지 않았다.

## 저장 위치와 경계

기본: `<프로젝트 루트>/.somssi-local`. `store.sqlite`는 운영 기록/프로젝트/로컬 사용자/관계/감사 이력, evidence 하위 폴더는 원본 파일이다. 최초 실행은 빈 운영 기록과 기본 프로젝트만 만들고 샘플 실적을 수입하지 않는다. 폴더0700·DB/신규 증빙0600, Git ignore, public 경로 거부, UUID 기반 파일 경로와 다운로드 해시 검증을 적용했다.

선택적으로 서버 환경의 SOMSSI_DATA_DIR에 절대 경로를 지정할 수 있다. 경로를 바꿔 앱을 재시작하면 그 위치의 로컬 DB를 사용한다. 기존 폴더는 이동·삭제·덮어쓰지 않는다. 다른 경로의 빈 DB가 열렸다고 기존 데이터가 삭제된 것은 아니다. public/.git/.next/원본 폴더를 운영 저장 위치로 사용할 수 없다. 사용자 지정 폴더를 Git 관리 위치에 두지 않는다.

계정 로그인·클라우드 키 없이 동일 컴퓨터/운영체제 계정의 단일 운영 공간으로 사용한다. ‘로컬 사용자’는 감사 행위자 식별값이며 계정 인증을 완료했다는 의미가 아니다. 팀원/외부 협력자 people 기록은 업무용 데이터로 유지하되 앱 사용자별 접근 제한·온라인 공동 편집은 제공하지 않는다.

개발/운영 실행은 127.0.0.1 바인딩을 유지한다. 데이터 API는 localhost/127.0.0.1/IPv6 loopback Host만 허용하며 외부 Origin/Sec-Fetch-Site 요청을 차단한다. 브라우저 캐시를 금지한다. 같은 컴퓨터의 다른 프로세스/사용자에 대한 접근 보안은 OS 계정·파일 권한에 의존한다. 공용 서버나 공개 호스팅에 배포하지 않는다.

## 데이터 구조와 보존

Node.js 내장 node:sqlite를 사용한다. 새 DB의 schema version은1이다. projects/identity/records/record_links/audit_logs를 만들고 기존 도메인 명세/Zod·공통 집계를 재사용한다. UUID/동일 프로젝트·종류 참조·버전 충돌·불변 원장·정정 합계·LOI/계약 증빙 구분을 저장 계층에서도 검사한다. WAL, synchronous=FULL, FK, 5초busy timeout을 사용한다.

`BEGIN IMMEDIATE` 안에서 검증→기록/관계 갱신→DB 트리거의 감사 기록→커밋한다. 실패하면 함께 롤백한다. 지출/증빙/완료 결제 수정·기록 삭제·감사 이력 수정/삭제를 SQL 트리거로도 차단한다. 정정 거래는 원거래를 참조하는 추가 기록이다. 외부 파일 변경은 다운로드·백업 해시 검사에서 실패로 표시한다.

기존 데이터가 있는 DB를 초기화하지 않는다. 알 수 없는 스키마/새 버전/손상/권한·디스크 오류는 실패로 알리고 임시 메모리나 localStorage 저장으로 대체하지 않는다. 기존 Cloud 저장소가 실제 연결된 적이 없어서 이번 전환에 원격 데이터 이관은 수행하지 않았다. 과거에 별도 DB에 실제 데이터를 넣었다면 별도 백업/검증 이관이 필요하다.

## 전체 백업과 복구

설정 → 증빙 포함 전체 백업:

1. SQLite 공식 backup API로 일관된 DB 스냅샷 생성.
2. 스냅샷에 연결된 불변 증빙만 수집하고 파일 크기/SHA-256 확인.
3. manifest·DB·증빙을 gzip으로 압축. 임시 파일은 완료/취소 후 정리.

`.somssi-backup.gz`는 암호화되지 않은 개인정보 포함 가능 파일이므로 Git/public 밖에 보관한다. JSON 내보내기는 기록/감사 전용이며 바이너리를 복구하는 전체 백업과 구분한다. 전체 백업은 DB 파일당64MB, 증빙 업로드 파일당10MB, 합계512MB·최대10,000개 증빙 범위를 지원한다. 초과/변조/누락은 실패하며 성공한 백업으로 표시하지 않는다.

```sh
npm run local:restore -- /absolute/backup.somssi-backup.gz /absolute/NEW-private-directory
```

존재하지 않는 새 폴더에만 복구한다. 경로 이탈·중복·파일 해시/크기·SQLite integrity/FK·기록/감사 최신 버전·증빙 메타데이터 일치를 검증한다. 실패하면 이번에 만든 새 대상만 정리하고 원래 운영 폴더는 건드리지 않는다. 복구가 끝나면 SOMSSI_DATA_DIR를 복구 폴더로 바꾸고 앱을 재시작한다. 원본 폴더도 별도로 보존한다.

실행 중 store.sqlite만 수동 복사하면 WAL의 최신 기록이 빠질 수 있다. 앱의 전체 백업을 사용하거나 앱을 완전히 종료한 상태에서 운영 폴더 전체를 보존한다. 자동 클라우드 백업·동기화는 하지 않는다.

## 검증 범위

로컬 단위10개: 빈 DB·비밀값 불필요·파일 권한/재시작, 감사 원자성/버전 충돌, 재무 원본/정정/합계, 입력/관계 무결성, LOI 구분/파일 경로, Host/Origin 차단, 다중 연결, 증빙 포함 백업/새 폴더 복구/해시 불일치 거부. 기존 계산·역사적 PG 계약23개와 함께 총33개 테스트를 수행한다.

API 통합은 합성 인증 게이트웨이를 제거하고 실제 Next.js → 디스크 SQLite → 로컬 파일 경로를 사용한다. 계정 없이 저장, 파일 업로드/바이트/해시, 집계/정정/충돌, 외부 출처/Host 거부, JSON/전체 백업 복구, 실제 앱 프로세스 재시작 후 기록/파일 보존을 검사한다. 자세한 실행 결과는 TEST_PLAN.md를 따른다.

기존 공식 출력 미구현, 외부 예산 원본 전체 UI 회귀 미검증 등의 범위는 유지한다. 로컬 저장 전환으로 공식 제출 적합성을 주장하지 않는다.

기술 확인: [설치 Node22.21 SQLite API](https://nodejs.org/download/release/v22.21.0/docs/api/sqlite.html), [Next Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route), 설치된 Next 문서와 실제 node:sqlite 동작을 확인했다.

## 변경 파일 묶음

- `lib/local/store.ts`: SQLite 초기화·영속 저장·관계/재무 검증·감사 트리거.
- `lib/local/access.ts`, `server.ts`: loopback/Origin 보호·로컬 연결·오류 응답.
- `lib/local/archive.ts`, `scripts/restore-local.mjs`: 증빙 포함 스냅샷 백업·해시/무결성 검증·새 폴더 복구.
- `app/api/*`: 기존 저장/조회/증빙/백업 API의 로컬 전환. 과거 로그인/로그아웃 요청은410으로 로컬 모드를 안내.
