# 원본 문서 필드매핑 설계

M0에서 원본 바이너리/OOXML을 조사했다. 아래는 M5 구현용 후보이며 실제 주입·렌더 검증은 아직 수행하지 않았다. 인덱스는 document.xml의 모든 tbl을 문서 순서로 펼친 0 기반 값이다. 중첩 표/도형/대체 콘텐츠가 있어 python-docx의 document.tables 인덱스와 동일하다고 가정하면 안 된다. XPath+라벨+원본 해시를 함께 고정한 버전 매핑을 작성한다.

| 원본               | 입력 데이터                                               | 조사 위치(표/행/셀 0 기반)             | 보존·검사                                                        |
| ------------------ | --------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------- |
| 활동비 증빙        | 활동 목적/일시/장소                                       | t3 r0 c3, r1 c1/c3                     | 라벨/병합/실행별 날짜 고정                                       |
| 활동비 증빙        | 총액/비목/집행일/세부내용/금액                            | t3 r2 c1 내 총액 런, 중첩 t4 r1–3 c0–3 | 총액 런만 교체, 중첩 표 지우지 않음                              |
| 활동비 증빙        | 현장 사진                                                 | t3 r3 c1                               | 원본 영역, 최소 1장 규정 버전 검사                               |
| 회의록             | 일시/장소/목적                                            | t3 r0 c3/c5, r1 c1                     | 시간/표 높이/페이지 보존                                         |
| 회의록             | 본문/결정/참석자                                          | t3 r2 c1                               | 기존 안내문·금액 규칙을 전부 덮지 않고 지정 런만 치환            |
| 회의록             | 사진/서명                                                 | t3 r3 c1, r5–6 c0–1                    | 사진 최소 1장, 참석자별 관계검증·서명 연결                       |
| 구매 사유서        | 신청자/기관/생년월일/연락처/아이디어                      | t3 r0–2                                | 개인정보 별도 권한                                               |
| 구매 사유서        | 물품명/부가세 포함 총액/사업 연관성                       | 중첩 t4 r0 c1/c3, r1 c1                | 실제 지출 연결, 총액 대조                                        |
| 구매 사유서        | 사진/임차 불가/신청일·서명                                | t4 r2 c1, t5 r0 c0, t6                 | 사진 최소 2장, 원본 서명 좌표 확인 후 주입                       |
| 팀원 참여 확인서   | 대표자/기관/생년월일/연락처/아이디어                      | t4 r0–2                                | 템플릿의 예시 인물을 실데이터로 취급하지 않음                    |
| 팀원 참여 확인서   | 성명/관계/소속/기간/역할/서명                             | 중첩 t5 r1–5 c0–6                      | 고정 5행 용량 초과 시 검토 필요, 자동 행 확장 금지               |
| 팀원 참여 확인서   | 신청일/대표 서명                                          | t6                                     | 원본 위치 보존                                                   |
| 집행 상세내역 XLSX | 연번/권역/선정자/집행항목/비목/내용/거래처/일자/금액/증빙 | 첫 시트 A6:J26 (21행)                  | 예시 4건을 데이터로 수입하지 않음, 등록된 출력 스냅샷으로만 치환 |

Excel 시트명·정의이름·인쇄 범위·유효성은 original-inventory.json에 원문 기록. I27의 SUM(I6:I26), 병합 A1:D1 / A4:J4 / A27:H27 / A29:G29 보존. 21건을 넘으면 자동 행 추가나 인쇄영역 변경 대신 사용자 검토로 차단한다. 원본의 ‘필요시 칸 추가 가능’ 문구가 있더라도 이 시스템은 사용자 허락 없이 구조를 바꾸지 않는다.

매핑 버전에는 원본 SHA-256, XML 파트/라벨/XPath, 대상 데이터 경로, 필수 여부, 날짜/금액 포맷, 글자수·사진 영역, 규정 버전, 넘침 시 처리 방법을 기록한다. 신규 version일 때만 원본을 추가 등록하며 이전 바이너리는 덮어쓰지 않는다.

생성 순서: 서버 인가 → 규정/원본 버전 고정 → 입력 필수값 검사 → 데이터 스냅샷 → 원본 복제 → 정의 영역 주입 → OOXML 구조·수식·스타일 검사 → Word 렌더 PNG 및 Excel 렌더/인쇄 검증 → validated 상태 → 권한 확인 다운로드. generated만으로 제출 완료 처리하지 않는다.

표 제목/설명용 도형 안의 tbl과 실제 데이터 표를 구분해야 한다. 런 전체 교체나 cell.text 대입으로 서식·중첩 표가 소실될 수 있으므로 M5에서 선택한 런/텍스트 노드만 변경한다. 현재 좌표는 구조 조사 수준이며 사진/서명 bounding box와 실제 앱 렌더 비교는 미완료다.
