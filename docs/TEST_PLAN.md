# M1 테스트 결과와 이후 검증

검증일 2026-10-27. 프론트엔드가 고정 데모 데이터를 표시하고, 메뉴 이동·필터가 동작하며, 구현되지 않은 기능을 작동한다고 오인시키지 않는 것이 이번 사용자 시나리오다. 실제 업무·승인·파일 처리·DB/API는 대상이 아니다.

## 재현 절차

1. npm ci, npm run build, npm run start 실행 후 별도 터미널에서 npm run test:smoke.
2. /tasks에서 검색 ‘보완’ → 진행 막힘 1건, 상태 ‘완료’ → 0건, 초기화 → 4건 확인.
3. 390px 화면에서 메뉴 열기 → 종합 대시보드 → 메뉴 닫힘/현재 페이지 표시 확인.
4. /documents의 모든 생성 버튼과 /login의 로그인 버튼이 비활성인지 확인.
5. /budget/allocate에서 원본 링크를 열고 기존 화면을 이용. 이 앱에 편성 결과를 저장했다고 표시되지 않는지 확인.
6. 원본 자료가 있는 작업 환경에서는 npm run verify:originals 실행. Git에는 원본 바이너리/HTML 사본이 없어야 함.

scripts/browser-smoke.js는 agent-browser eval --stdin 또는 브라우저 개발자 도구에서 실행할 수 있다. 이 환경에서는 stdin 리다이렉션도 소켓 권한 제약이 있어 CLI eval -b로 실행했다. 브라우저 404 요청에 따른 네트워크 상태는 의도한 검사이며 앱 JS 예외와 구분한다.

## 남은 단계의 필수 게이트

M2 이후 원 명세 11절 E2E 10개를 단계에 맞춰 실행한다. 로그인·다른 프로젝트 접근 거부·공유 데이터 영속성·낙관적 잠금, 5만 승인/4만 집행/1만 약정, 증빙 누락 거래 보존, 파일 해시 중복 의심, 규정 버전별 초과, 서명·사진 포함 4 DOCX/1 XLSX 구조·렌더 검사, 기존 배분표 전체 계산/디자인 회귀는 미검증이다. M1 통과로 이 기능들이 완성됐다고 간주하지 않는다.

## V2 현행 분석·기준 정비 (2026-10-29)

브랜치: feat/v2-analysis-baseline. 사용자 요청 단계1과 단계2 일부, 읽기 전용 준비 화면/순수 집계 기반의 검사다. 전체 V2 완성·CRUD·공식 출력의 검증 결과가 아니다.

- lint / typecheck / production build: 통과. 변경 후 최종 재실행 결과 확인.
- test:unit: 7/7 통과. 세 자금/편성/실집행/정정 분리, 설문과 인터뷰·실제 선결제 구분, 운영 완료 파일럿, 계약 증빙, 공헌이익 재계산·미입력·안전 정수, 마감 경계, 계획/미검증 실적 제외.
- test:smoke: 통과. 19개 페이지 200, 루트307, 잘못된/비공개5경로404, 기본 대시보드 샘플40만원 미표시, 데모 별도 경로, 신규 페이지, 문서생성5버튼 disabled. 최초 샌드박스 localhost EPERM은 실패로 기록하고 승인된 샌드박스 밖 동일 명령으로 통과했다. 검증 서버 포트는 3101(최종 재빌드 재검사 3102).
- verify:originals: Office5종+HTML4종 SHA-256 일치. 원본 변경 없음. 예산 전체 UI 회귀 재실행과는 다름.
- 브라우저: agent-browser 격리 세션. 데스크톱 대시보드 스크린샷 시각 확인, 제출시간 표시·샘플 배제 확인. 업무 ‘보완’검색1건→완료 필터0건/빈안내→초기화4건 확인. 최초 초기화 선택자 오류는 올바른 버튼 선택자로 재검사했다.
- 모바일390×844: 메뉴 열기→가야금 상품 이동→메뉴 닫힘 확인, 상품 화면 scrollWidth <= innerWidth, 스크린샷 시각 확인. 브라우저 JS 오류 출력 없음.
- ego-browser는 초기 설정을 요구하여 작업 공간/페이지가 만들어지지 않았다. 사용 가능한 agent-browser로 전환. react-best-practices 검토: 기존 Server Component 유지, 클라이언트는 시계와 기존 메뉴/필터만, 타이머 해제·hydration 초기값·시맨틱 표/알림·배지 상태/모바일 메뉴 확인.
- 데이터 흐름: reference 계획/명시적 빈 OperatingData → 순수 summarize → 서버 페이지 → 시계 hydration. API/인증/DB/파일 경계는 존재하지 않으므로 검증하지 않음.
- 단위 테스트는 Node22의 experimental-strip-types를 사용하며 MODULE_TYPELESS_PACKAGE_JSON 경고가 있다. 동작 실패는 아니며 앱 모듈 설정은 변경하지 않았다.
