# 업무 이력과 정기 회의 캘린더 기록

적용일: 2026-10-30. 브랜치: feat/team-meetings-and-program-deadlines.

## 기록 범위

사용자가 제공한 업무 대화 캡처8장·직접 확인한 회의 이력·운영기관 안내문을 기존 calendarEvents에 등록했다. 기존24개 계획을 유지하고48개를 추가해 총72개 일정, 비공개 증빙8개, 누적감사101개가 됐다. 기존2개 계획 설명에는 보고서 제출과 자금 사용/증빙 제출 마감이 서로 다름을 보충했다.

완료한 회의3회는 사용자의 날짜·회차 확인에 근거한다. 향후 화·목 회의10회는 현재 운영 범위의 최종 증빙 마감까지 일자별로 등록했다. 반복 규칙으로 무기한 자동 생성하는 기능은 아니며 이후 기간은 필요 시 추가한다. 미제공 시간/장소/참석자는 만들지 않고 날짜만 표시했다. 회차별 실제 안건·결정·참석 정보가 없어 공식 회의록 레코드나 Word 회의록을 임의 생성하지 않았다.

과거 업무는 공유·통화·자료 준비가 확인된 범위만 완료로 기록한다. 파일명/링크가 보인다고 원본 문서 검토, 상품 운영, 외부 게시, AI 신청/선정/활용, 호텔 계약, 상표출원, 정산 제출이 완료됐다고 취급하지 않는다. 해당 결과는 확인 업무와 계획으로 구분했다. 날짜가 잘려 확인되지 않는 캡처 내용은 정리일을 관리일로 사용하고 본래 작성일 미확인을 설명에 적었다.

기관 안내의 사업계획/활동보고 플랫폼 제출, AI2차 신청 기간, 자금 사용 종료, 집행 신청서/증빙 최종 제출을 별도 일정으로 관리한다. 주차별 자료 제출은 자금 집행 후 즉시 회계법인에 전달하는 흐름으로 기록했다. 자체 점검 날짜는 운영기관이 지정한 제출 요일이 아니며 최종 마감일까지 모아서 제출하는 일정이 아니다. 미확인 지급 소요일·정산 입금일을 확정하지 않았다.

## 비공개 저장과 재실행

개별 업무 내용·대화 원문·캡처·연락 내용·영수증 등은 운영DB/비공개 파일에만 저장한다. Git의 기본 계획 정의나 데모에 넣지 않았다. 로컬 작업용 manifest와 실행 스크립트는 `.somssi-local/imports`(폴더0700/파일0600)에 있다. 등록은 기존 POST /api/records와 /api/evidence/upload를 사용해 서버 검증·버전·감사 트랜잭션을 거쳤다. API/스키마/예산 원본/Office 원본 변경은 없다.

일정은 고정 ID로 존재 여부를 확인해 누락된 것만 추가하고 증빙은 SHA-256으로 재사용한다. 이미 있는 일정을 재등록하거나 덮어쓰지 않는다. 사전 백업과 완료 후 증빙 포함 전체 백업은 `.somssi-local/backups`에0600으로 보관했다. 실제 최종 백업을 새 비공개 임시 폴더로 복구하여72개 일정/8개 증빙/101개 감사를 확인한 뒤 임시 검증 사본을 정리했다.

캡처 속 영수증에서 거래일/금액/회의 연계가 확정되지 않아 지출 원장을 만들지 않았다. 실제 매출/지출/파일럿 실적은 이번 등록으로 증가하지 않았다. 캡처는 증빙 원본이나 정산 적격성 확인을 대신하지 않는다.

## 화면 보완과 사용법

실행 일정은 현재 한국 날짜의 월/날짜로 열린다. 날짜의 숫자나 더 보기로 전체 상세 목록을 확인하고, 일정 수정에서 내용·날짜·시간·색상을 변경한다. 팀 회의는 분홍색으로 등록했다. 날짜별 상세 목록의 연결 증빙 링크로 해당 비공개 파일을 내려받을 수 있다. 원본 파일은 public에 배치하지 않으며 기존 로컬 다운로드 API의 Host/Origin·해시 검사를 유지한다.

변경 파일: components/schedule/schedule-calendar.tsx(오늘 기준 시작·증빙 링크), app/globals.css(증빙 링크 배치), scripts/smoke.mjs(고정월 대신 유효 날짜 추가 버튼 확인), 이 문서와 TEST_PLAN.md. 개인 운영 기록과 캡처는 커밋 대상이 아니다.
