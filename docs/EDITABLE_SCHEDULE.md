## 변경 내용과 사용법

실행 일정 `/schedule`에서 바로 월간 달력을 연다. 날짜 숫자를 누르면 해당 일자의 상세 목록, 날짜 옆 `+` 또는 상단 `일정 추가`를 누르면 입력 폼이 열린다. 제목·시작/종료일·종일/시간·분류·상태·색상(8종)·세부 내용·담당자·관련 업무/가설·출처·확인일·검증 상태를 입력하고 저장한다. 이름이나 상세 목록의 `일정 수정`으로 편집한다. 불필요한 일정은 취소로 남기며 삭제하지 않는다. 여러 날 일정은 포함된 날짜마다 표시된다. 하루에 3개를 넘으면 `더 보기`로 전체 상세 목록을 볼 수 있다. 분류/상태 필터, 전월/다음월/오늘 이동을 지원한다. 시간은 KST이다.

사용자 제공 V2 사업 방향과 초기 마일스톤에 맞춰 19개의 계획을 작성했다. 고객 문제/경쟁 조사 → 60분 MVP·설문·견적 → 초기 파일럿 → 유료 검증·협력·원가 → Q1–Q4·활동보고·정산 → 최종검증 → 11월23일14시 마감이다. 첫 화면은 제출 준비 기간인 2026년11월이다. 최종개정 사업계획서 DOCX는 미확보이므로 원본과 대조한 확정 일정으로 표시하지 않는다. 멘토링/파일럿 날짜는 협의·검증할 계획 구간이다.

빈 저장소에서는 `초기 계획 19개 추가`로 등록한다. 기존 계획 ID는 건드리지 않고 누락된 ID만 추가하므로 중간 중단 뒤 재시도할 수 있다. 일정은 실적과 별개이며 실제 파일럿·결제·멘토링·제출 완료를 자동 생성하지 않는다. 기존 업무와 마일스톤도 함께 보여주고 해당 원래 관리 화면에서 편집한다. 원본 외부 일정 앱은 접힌 참고 링크로만 남겼다. 기존 예산 앱과 Office/HTML 원본 파일을 수정하지 않았다.

## 파일·저장 구조

- app/(main)/schedule/page.tsx: 기존 외부 링크 중심 화면을 내부 달력으로 연결.
- components/schedule/schedule-calendar.tsx, app/globals.css: 달력/날짜 상세/편집/색상/필터와 반응형 표시.
- lib/operations/calendar.ts, data/reference/schedule-plan.ts: 한국 날짜·달력 투영과 출처를 명시한 초기 계획.
- lib/operations/domains.ts, validation.ts: calendarEvents 필드와 날짜/시간/기간/색상 검증.
- lib/navigation.ts: 기능 설명 갱신.
- scripts/smoke.mjs, tests/calendar.test.mjs, tests/operations-integration.mjs: 신규 달력·실제 API·재실행/백업 회귀 검증.
- 과거 SQL 마이그레이션의 생성된 도메인 규칙은 기존 계약 테스트와 일치하도록 재생성했다. 클라우드를 사용하거나 연결하지 않는다.

기존 로컬 records/record_links/audit_logs에 저장하므로 DB를 초기화하거나 기존 기록을 덮어쓰는 마이그레이션이 없다. 기존 POST /api/records를 재사용했으며 Next.js API/인증 경계 변경은 없다. 충돌 시 입력 폼을 유지하고 서버 오류를 표시한다. 현재 서버 목록을 새로고침한 뒤 수정 항목을 다시 열어 재시도한다. 모든 변경은 서버 감사에 기록되고 증빙 포함 전체 백업에 포함된다.

## 실행·제약

Node>=22.16, `npm install`, `npm run dev` 또는 `npm run build` 후 `npm run start`. 주소 http://127.0.0.1:3100/schedule. 클라우드 계정·키·로그인 없이 사용한다.

원본 사업계획서 DOCX/HWP가 확보되면 계획의 내용·실제 운영일·가격·담당자를 대조해야 한다. 이전 외부 앱의 브라우저 데이터는 자동 수입하지 않는다. 달력은 드래그 이동·외부 캘린더 동기화를 제공하지 않으며 입력 폼으로 날짜를 변경한다. 공식 문서 생성/페이지 렌더 검증은 이번 일정 기능의 완료 범위에 포함하지 않는다.

실제 운영 적용: 변경 전 전체 백업을 `.somssi-local/backups/before-calendar-20261030.somssi-backup.gz`에 보관한 뒤 초기 계획19개를 등록했다(감사19개, 모두 계획). 테스트 입력은 임시 프로젝트에만 작성했다. 완료한 검사와 미완료 범위는 TEST_PLAN.md의 상세 일정 달력 절에 기록했다.
